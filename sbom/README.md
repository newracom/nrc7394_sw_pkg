## What is in the SBOM

15 components, of which 15 are curated by hand
rather than detected by a scanner. Automated detection only sees package-manager
metadata, and this package has almost none of that: the host driver and
applications are shipped as source, the device firmware is a statically linked
image whose third-party contents were established from its linker map, and the
bundled Wireshark packages are Debian archives with no installed package
database to read. Every curated component is published with a PURL and, where
one exists, a CPE, so that it can be matched against CVE data by your own
tooling. Components that exist only inside the firmware image are marked with
the `newracom:source` property.

## Scan scope

The SBOM describes the contents of the released package. The following paths are
deliberately excluded because they are build-time or upstream-maintainer
material that is not installed on, nor executed by, the target device:

| `**/docs/**` | Upstream documentation build toolchains (Sphinx/Doxygen Python requirements). Not cross-compiled, not installed on the host, not executed on the device. |
| `**/doc/requirements*.txt` | Documentation build dependencies only. |

| `**/ci/**` | Continuous integration helpers; not shipped. |
| `**/test/**` | Unit test sources and fixtures; not built into the release image. |
| `**/tests/**` | Unit test sources and fixtures; not built into the release image. |
| `./sbom/**` | This tool's own output. |
| `**/sniffer/**/deb/**` | Bundled Wireshark/tshark .deb archives. A directory scan cannot read the package metadata inside them and would list each archive by file name with no version or licence. Excluding these keeps the vulnerability report about the product. Findings in a
documentation toolchain that never ships would otherwise be reported as product
vulnerabilities.
